# GraphQL

The integration talks only to Railway GraphQL v2:

```
https://backboard.railway.com/graphql/v2
```

The typed client lives in `src/Aspire.Hosting.Railway/GraphQL/`. Deploy calls `RailwayGraphQLApplyService`. Do not change the public AppHost surface when extending apply.

## Do not invent operations

Use confirmed operations only. Never invent mutation or query names. Never call `pluginCreate`. Deprecated and unused: `pluginCreate`, `templateDeploy` v1.

Unit tests stay offline. They inject a fake `HttpMessageHandler`. Do not fake GraphQL success in a way that hides a missing confirmed operation.

## Confirmed operations

| Operation | Role |
| --- | --- |
| `project` | Documented `project(id)` query. Lists `services`, `environments`, and `buckets` so apply can adopt by name. `buckets` is a field on the same confirmed query (Relay connection of `id` + `name`), not a new operation. |
| `projectCreate` | Creates a Railway project. Requires an account or workspace token. |
| `environmentCreate` | Creates an environment. Pass `sourceEnvironmentId` to duplicate production. `ephemeral` is reserved for later. |
| `serviceCreate` | Creates a service. Always pass `environmentId`. |
| `serviceInstanceUpdate` | Updates a service instance. Always pass `environmentId` (official docs and this apply path; live schema marks the argument optional). Confirmed `ServiceInstanceUpdateInput` fields used here: `source.image`; `multiRegionConfig` (JSON map of official `Region.region` id → `{ numReplicas }`, mapped from AppHost `RailwayRegion`); `sleepApplication` (`railway.json` `deploy.sleepApplication` — there is no GraphQL field named `serverless`; applies to all replicas); `numReplicas` as the documented single-region path when only `WithReplicas` is set ([autoscale](https://docs.railway.com/guides/autoscale-horizontally)); `healthcheckPath` (String) and `healthcheckTimeout` (Int seconds) verified on the live schema 2026-08-20 and [healthchecks](https://docs.railway.com/deployments/healthchecks); `restartPolicyType` (`RestartPolicyType`: `ALWAYS` / `NEVER` / `ON_FAILURE`) and `restartPolicyMaxRetries` (Int) verified on the live schema 2026-08-20 and [restart policy](https://docs.railway.com/deployments/restart-policy); `startCommand` (String) and `preDeployCommand` (`[String!]`) verified on the live schema 2026-08-20, [start command](https://docs.railway.com/guides/start-command), and [pre-deploy command](https://docs.railway.com/deployments/pre-deploy-command); `overlapSeconds` (Int) and `drainingSeconds` (Int) verified on the live schema 2026-08-20 and [deployment teardown](https://docs.railway.com/guides/deployment-teardown); `cronSchedule` (String) verified on the live schema 2026-08-20 and [cron jobs](https://docs.railway.com/cron-jobs). Never send `numReplicas` and `multiRegionConfig` together. Omit unset healthcheck, restart-policy, start-command, pre-deploy, teardown, and cron fields; do not send `null`. Do not add `vCPUs` / `memoryGB` onto this input. See [regions](https://docs.railway.com/deployments/regions), [multi-region configuration](https://docs.railway.com/reference/config-as-code#multi-region-configuration), and [scale](https://docs.railway.com/cli/scale). |
| `serviceInstanceLimitsUpdate` | Updates per-replica CPU and memory after the service id exists. Confirmed on the live schema (`ServiceInstanceLimitsUpdateInput`, 2026-08-20) and [manage services](https://docs.railway.com/guides/manage-services). Always pass `serviceId` and `environmentId`. Optional floats: `vCPUs`, `memoryGB`. Return is `Boolean!`. Railway staff confirmed this mutation on [Central Station](https://station.railway.com/questions/programmatically-setting-instance-memory-016d6ad4) (2026-02); older no-op reports were later marked fixed. Do not invent other limit mutations or fields. Related reads (`serviceInstanceLimits`, `serviceInstanceLimitOverride`) exist and are not used. Config-as-code mapping only: `deploy.limitOverride.containers` (`cpu` / `memoryBytes`) in [railway.schema.json](https://railway.com/railway.schema.json) — GraphQL uses GB and vCPU floats, not bytes. Not sent for managed Postgres / Redis / buckets. |
| `serviceInstanceDeployV2` | Deploys a service instance from its current `source.image`. |
| `variableCollectionUpsert` | Upserts service or shared variables. |
| `serviceDomainCreate` | Creates a Railway-provided HTTP domain. Optional confirmed `targetPort` Int (live schema 2026-08-20) is sent when the Aspire HTTP endpoint has one. Omit when unset. |
| `domains` | Lists Railway-provided and custom domains for a service. Confirmed `domains(environmentId, projectId, serviceId)` returns `AllDomains` (`customDomains`, `serviceDomains`). Always pass all three ids. Live schema 2026-08-20. |
| `customDomain` | Reads one custom domain by id. Confirmed `customDomain(id, projectId)`. Used to re-query status after adopt. `verificationToken` lives on `CustomDomainStatus`, not on `DNSRecords`. Live schema 2026-08-20. |
| `customDomainAvailable` | Checks whether a hostname can be added. Confirmed `customDomainAvailable(domain)` returns `DomainAvailable { available, message }`. Live schema 2026-08-20. |
| `customDomainCreate` | Creates a custom hostname. Confirmed `CustomDomainCreateInput`: `domain`, `environmentId`, `projectId`, `serviceId` required; optional `targetPort` Int. Omit unset; do not send `null`. Live schema 2026-08-20. Do not call `customDomainDelete` or `customDomainIssueCertificate` on this path. |
| `customDomainUpdate` | Updates an adopted domain's target port. Confirmed `customDomainUpdate(environmentId, id, targetPort)`. Call only when the known Aspire HTTP target port differs. Always pass `environmentId`. Live schema 2026-08-20. |
| `template` | Fetches a template by code. Use the returned `id` as `templateId` and the returned `serializedConfig`. Never invent template UUIDs. |
| `templateDeployV2` | Deploys that fetched template. |
| `workflowStatus` | Polls a workflow started by template deploy. Apply fails if `workflowId` is missing. |
| `bucketCreate` | Creates a Railway storage bucket. Region is immutable after create. |
| `bucketS3Credentials` | Reads S3 credentials. `projectId` is required. Select `bucketName` (not `bucket`). Do not persist the secret. |
| `environmentPatchCommitStaged` | Commits staged environment patches. |
| `regions` | Lists Railway regions. |
| `environment` | Confirmed `environment(id: String!, projectId: String)` (live schema 2026-08-20). Selects `volumeInstances` (`EnvironmentVolumeInstancesConnection` of Relay `edges` / `pageInfo`). Edge type is `EnvironmentVolumeInstancesConnectionEdge` (`cursor`, `node`). `VolumeInstance` fields used here: `id`, `serviceId`, `volumeId`, `environmentId`, `mountPath`. Match `serviceId` to the official Postgres template service id after `templateDeployV2`. Retry if the instance is not visible yet. Do not use `adminVolumeInstancesForVolume`. Do not use `volumeInstance(id)` unless the id is already known. Service has no `volumes` field; ServiceInstance has no `volume` field. |
| `volumeInstanceBackupScheduleList` | Lists schedules for one volume instance. Confirmed `volumeInstanceBackupScheduleList(volumeInstanceId: String!)` returns `[VolumeInstanceBackupSchedule]` (a list, not a connection). Fields: `id`, `kind`, `name`, `cron`, `createdAt`, `retentionSeconds`. Live schema 2026-08-20. |
| `volumeInstanceBackupScheduleUpdate` | Replaces the schedule kinds set. Confirmed `volumeInstanceBackupScheduleUpdate(kinds: [VolumeInstanceBackupScheduleKind!]!, volumeInstanceId: String!)` returns `Boolean!`. Enum: `DAILY`, `WEEKLY`, `MONTHLY`. No input wrapper. Omit unset; do not send `null`. Apply unions requested kinds with already-present kinds so a dashboard schedule this plan did not mention is not removed. Live schema 2026-08-20. |

Documents are in `RailwayGraphQLOperations`. Confirmed operations do not include project or environment delete; `destroy-{name}` does not invent those mutations, and must not invent backup or volume deletes (`volumeInstanceBackupDelete` is confirmed on the live schema but is not used). `overlapSeconds` / `drainingSeconds` are **in-deploy lifecycle** (zero-downtime cutover on `serviceInstanceUpdate`), not `aspire destroy`.

Official Postgres volume backup schedules use `environment` + `volumeInstanceBackupScheduleList` + `volumeInstanceBackupScheduleUpdate` (live schema 2026-08-20). AppHosts set `VolumeBackupDaily` / `VolumeBackupWeekly` / `VolumeBackupMonthly` on `PublishAsRailwayPostgres`. Core apply reads `volumeBackupScheduleKinds` from the managed-service plan object without referencing the PostgreSQL hosting package. Do not call `volumeInstanceBackupCreate` / `Delete` / `Lock` / `Restore`, `volumeInstancePITRRestore`, `enablePitrForHaCluster` / `disablePitrForHaCluster`, `pluginCreate`, or `cronCreate`. PITR enable mutations on the live schema are HA-only; non-HA PITR enable is not a confirmed public mutation. Do not invent `WAL_ARCHIVE_*` or `bucketCreate` of `Postgres-PITR`.

`serviceInstanceUpdate` is the only mutation that sets compute scale, region, `sleepApplication`, deploy healthcheck (`healthcheckPath` / `healthcheckTimeout`), restart policy (`restartPolicyType` / `restartPolicyMaxRetries`), start command (`startCommand`), pre-deploy (`preDeployCommand`), deployment teardown (`overlapSeconds` / `drainingSeconds`), and cron (`cronSchedule`). `serviceInstanceLimitsUpdate` is the only mutation that sets per-replica `vCPUs` / `memoryGB`. Do not add those fields onto `ServiceInstanceUpdateInput`. `serviceCreate` does not take those fields. `multiRegionConfig` is a JSON scalar (`{ "us-west2": { "numReplicas": 2 } }`). `ServiceInstance` has no `multiRegionConfig` read field; do not invent a read-back query. AppHosts set `RailwayRegion`; apply maps members to official `Region.region` strings (`us-west2`, `us-east4-eqdc4a`, `europe-west4-drams3a`, `asia-southeast1-eqsg3a`), not `Query.regions.id` airport codes. Cap total replicas at 50 (product/CLI docs). Replicas cannot be used with [volumes](https://docs.railway.com/volumes/reference); do not send `numReplicas` / `multiRegionConfig` / `serviceInstanceLimitsUpdate` / `healthcheckPath` / `healthcheckTimeout` / `restartPolicyType` / `restartPolicyMaxRetries` / `startCommand` / `preDeployCommand` / `overlapSeconds` / `drainingSeconds` / `cronSchedule` for `PublishAsRailwayPostgres` / `PublishAsRailwayRedis`. Do not invent other scale, limit, healthcheck, restart-policy, start-command, pre-deploy, teardown, or cron mutations or fields. Do not invent `cronCreate` / `scheduleCreate`. Do not use `environmentPatchCommit` / staged patches for CPU/RAM, healthcheck, restart policy, start command, pre-deploy, teardown, or cron in v1. Config-as-code mapping only: `deploy.healthcheckPath` / `deploy.healthcheckTimeout` / `deploy.restartPolicyType` / `deploy.restartPolicyMaxRetries` / `deploy.startCommand` / `deploy.preDeployCommand` / `deploy.overlapSeconds` / `deploy.drainingSeconds` / `deploy.cronSchedule` in [railway.schema.json](https://railway.com/railway.schema.json). Railway probes until HTTP 200, then flips traffic; origin host is `healthcheck.railway.app`; volume-backed services still have cutover downtime. Unset restart-policy fields leave Railway's default (On Failure / 10 retries). AppHosts set `RailwayRestartPolicy`; apply maps members to `ON_FAILURE` / `ALWAYS` / `NEVER`. These restart-policy input fields were confirmed on the live schema 2026-08-20. Unset `startCommand` leaves the image ENTRYPOINT/CMD. Image/Dockerfile start is exec form — wrap `$PORT` as `/bin/sh -c "exec … $PORT"`. AppHosts set a single `PreDeployCommand` string; apply sends `[String!]`. Pre-deploy cannot touch volumes. These start/pre-deploy input fields were confirmed on the live schema 2026-08-20. Aspire `WithArgs` is not mapped. AppHosts set `OverlapSeconds` / `DrainingSeconds`; apply sends GraphQL Ints on the same `serviceInstanceUpdate`. Either field can be set alone. Values must be greater than or equal to 0 when set (0 is no wait / immediate kill). These teardown input fields were confirmed on the live schema 2026-08-20. Config-as-code examples type them as strings; GraphQL wants Int. `RAILWAY_DEPLOYMENT_OVERLAP_SECONDS` / `RAILWAY_DEPLOYMENT_DRAINING_SECONDS` are documented variables, not the apply path. AppHosts set `CronSchedule`; apply sends GraphQL String `cronSchedule` on the same `serviceInstanceUpdate`. Unset omits the field (always-on). Five-field crontab, UTC, minimum every 5 minutes. Empty or whitespace fails. Combining cron with replicas greater than 1 or `Serverless = true` fails. The service must exit; if still running at the next tick, Railway skips. This cron input field was confirmed on the live schema 2026-08-20.

`project.buckets` is a field on the documented `project(id)` query (Relay `edges { node { id name } }`, same shape as `services`). It was verified on Railway's GraphQL schema (`Project.buckets: ProjectBucketsConnection` of `Bucket { id name }`). There is no separate confirmed buckets-list query; apply does not invent one. `bucketInstanceDetails` is not a confirmed operation in this repo and is not used. After `bucketCreate`, apply retries the confirmed `bucketS3Credentials` query until a BucketInstance exists.

Custom hostnames use confirmed `domains` / `customDomain` / `customDomainAvailable` / `customDomainCreate` / `customDomainUpdate` (live schema 2026-08-20). AppHosts set `CustomDomains` hostname strings on `PublishAsRailwayService`. Requires `WithExternalHttpEndpoints()`. After the service id exists and after today's `serviceDomainCreate`, apply lists `domains`, adopts a same-hostname custom domain (case-insensitive), or creates. `customDomainUpdate` runs only when the known target port differs. Select `status.dnsRecords` (`fqdn`, `recordType`, `requiredValue`) and `status.verificationToken` / `verificationDnsHost` / `verified` / `certificateStatus` for the deploy report. Do not invent `dnsRecords.verificationToken` — the token lives on `CustomDomainStatus`. Report record types as Railway returned them; do not rewrite them to A records (Railway has no static IP). Do not call `customDomainDelete` (destroy is a later slice) or `customDomainIssueCertificate` (Railway issues Let's Encrypt after verify). Do not use `pluginCreate`, `environmentPatchCommit`, `railwayDomain*`, `trustedDomain*`, `cronCreate`, or `scheduleCreate`. Persist flatten-safe custom-domain **ids** only; verification tokens stay out of plan files and state. Not sent for `PublishAsRailwayPostgres` / `PublishAsRailwayRedis` / buckets. TCP proxies are out of scope. See [working with domains](https://docs.railway.com/networking/domains/working-with-domains) and [manage domains](https://docs.railway.com/integrations/api/manage-domains).
